# Landing page images

The landing page has six image slots (plus one optional). Each slot shows
a grey placeholder until a file exists at `public/marketing/<name>.webp`
(`.png` / `.jpg` also work). Drop the file in and reload — nothing else
to wire. The list below is generated by hand from `lib/landing-images.ts`,
which is the source of truth for names, sizes and alt text.

Two things to keep constant across all of them, because the page itself
is white, cool-grey and flat and the pictures carry the warmth:

- **UI shots**: white background, `#111827` text, `#f3f4f6` panels,
  `#eef0f2` hairlines, no gradients, no drop shadows, no device bezel
  unless the prompt says "phone". Text must be sharp and legible — if the
  model garbles text, regenerate; blurry UI text is the #1 tell.
- **Photos**: natural light, documentary feel, Indian context, no text
  overlays, no logos.

Sizes are the width×height the layout expects. Wider or taller is fine as
long as the ratio matches; the component scales it.

> For the hero and the two feature cards, a **real screenshot** of the
> app / a real Google listing will always beat a generated one. The
> prompts are there if you'd rather not.

## After you have the files

```
public/marketing/
  hero-dashboard.webp
  report-phone.webp
  whatsapp-approval.webp
  feature-posts.webp
  feature-reviews.webp
  owner-portrait.webp
```

Convert to WebP if you can (`cwebp -q 82 in.png -o out.webp`); PNG is fine
too, just heavier. The `/` route is prerendered, so in a production build
the image check runs at build time — re-run `next build` after adding
files. `next dev` picks them up on the next request.
